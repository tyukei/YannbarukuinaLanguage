コードはどうやって動く？

人が読むソースコードと、CPU が実行する機械語は別物です。その間に何があるか、C と Python を例にたどり、最後に Z80 の機械語を手で動かします。

  • ソースコードを書く
  • C：実行ファイルを作る
  • Python：処理系で実行する
  • CPU とメモリ：命令を取り出す
  • 実例：Z80 の機械語で 2 + 3

1. ソースコードを書く

誰が書いても、同じソースコードなら実行までの仕組みは同じです。LLM が生成したコードも、意図どおりかは読んで試して確かめます。

2. C：実行ファイルを作る

  1. 前処理：#include でファイルを取り込み、マクロを展開する。
  2. コンパイル：C の意味を調べ、対象 CPU 向けのアセンブリに変換する。
  3. アセンブル：機械語と、後で結び付けるための情報をオブジェクトファイルに格納する。
  4. リンク：別のファイルやライブラリにある関数などの参照をつなぎ、実行ファイルを作る。

実行時は OS が必要な部分をメモリに配置し、CPU が機械語を実行します。

3. Python：処理系で実行する

python hello.py と実行すると、一般的な処理系の CPython は、Python をバイトコードに変換してから、内部の仮想マシンで実行します。

「インタープリタを使う」ことは「途中で変換しない」という意味ではありません。CPython もバイトコードへのコンパイルを行います。

4. CPU とメモリ：命令を取り出す

PC（プログラムカウンタ）は、次に読み出す命令のアドレスを示す CPU 内のレジスタです。ここでの PC はパソコンの略ではありません。

メモリには実行中の命令やデータが置かれます。現代の CPU には、アクセスした命令やデータの一部を近くに保持する、小さくて高速なキャッシュがよくあります。必要な内容がキャッシュにあれば、メインメモリまで取りに行かずに済みます。

5. 実例：Z80 の機械語で 2 + 3

次の 5 バイトを使います。アセンブリは人が読む表記で、メモリに置くのは中央のバイト列です。

  1. Z80 エミュレータで、メモリの 0100h から 3E 02 C6 03 76 を書き込みます。raw バイナリの読み込み機能があれば、同じ 5 バイトを開始アドレス 0100h にロードします。上の文字列そのものをファイルに入れるのではなく、数値としての 5 バイトです。
  2. レジスタの PC を 0100h に設定して、1 命令だけ実行します。A = 02h、PC = 0102h になります。
  3. もう 1 命令進めると、A = 05h、PC = 0104h になります。最後の HALT で通常の命令実行が停止します。

結果の 5 は画面には出力されません。エミュレータのレジスタ表示で A を確認します。この例は、メモリと PC を操作できる Z80 エミュレータ向けです。

別の場所に置いた処理を呼び出す：CALL と RET

「呼び出して元に戻る」動きも試せます。エミュレータのメモリに次のバイトを書き込み、初期値を PC = 0100h、SP = F000h に設定します。SP はスタックの位置を示すレジスタです。

命令の詳細は Zilog の Z80 マニュアルを参照できます。

YanbaruKuina は Z80 向けのコードを生成し、ブラウザ内の Z80 エミュレータで実行します。 エディタに入力するのは高水準のソースコードで、上のような生の機械語バイトを直接入力する欄ではありません。CHUKEI は Z80 とは別の教材用 VM です。C を65回書いて CHUK を実行すると、セルの値65に対応するASCII文字 A が表示されます。CC CHUK ではセルの値は2になりますが、出力は画面に見えない制御文字です。CHUKEIのデバッグ実行でセルを見る。
